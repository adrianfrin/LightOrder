# 开始使用

[English](../en/getting-started.md) · [首页](../../README.zh-CN.md)

## 安装与启动

1. 使用 Windows 11 x64，并从 [Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/) 安装 Microsoft Edge WebView2 Evergreen Runtime。安装程序会检查它，但不会静默下载。
2. 从项目 [Releases](https://github.com/adrianfrin/LightOrder/releases) 下载 `LightOrder.exe`。阅读该版本的依赖清单、验证记录和 SHA-256 校验值。
3. 用日常 Windows 账户运行安装程序，批准首次管理员授权。程序安装 `LightOrder.Service`、受保护的插件和桌面应用，然后以普通权限启动界面。
4. 在设置中检查服务连接。启动时发现设备并读取状态，不会自动应用保存的灯光或风扇配置。OpenRGB 适配器可能在发现时启动已配置的后端，但发现不会设置灯效。
5. 选择设备，查看它实际支持的操作后再应用修改。

自包含安装包含 .NET；WebView2 仍是独立前置条件。构建成功不代表已经在干净机器上验证安装、升级或卸载。

## 灯光

选择设备、静态或关闭效果、颜色与亮度，再点击 **保存并应用**。编辑草稿不会写入硬件。亮度按比例缩放 RGB 输出，并非测量出的实际光强。

同步必须主动开启，且至少选择两个已有独立设置的合格设备。原状态未知时，请先独立保存一次。选择成员、编辑同步设置并保存。关闭同步后，再保存并应用，即可恢复加入前的已知独立设置。这里恢复的是光序知道的设置，不是无法读取的出厂颜色或安装前颜色。

部分设备失败会保留错误。重试前先核对各设备状态。命令已接受或 OpenRGB 缓存匹配不等于实物验证。写入结果不确定时不会自动重试。

## 散热

只有声明 `fan.profile` 的控制器才显示编辑功能。选择冷排或机箱，编辑曲线或手动百分比，再保存并应用。曲线需要 2–12 个节点，温度递增、占空比不下降，最后一点为 80°C / 100%。冷排最低 40%，机箱最低 25%。手动模式保留高温保护。水泵转速只读。

每次会话最长 **30 分钟或 1,800 次更新**。修改配置不会改变原截止时间。到期或点击 **恢复原始控制** 时会尝试恢复，请检查返回的恢复结果。百分比是占空比，不是固定 RPM。

温度或转速反馈缺失、风扇故障会触发恢复尝试。不要把有时限的实现用作无限期无人值守散热控制器。睡眠唤醒和崩溃恢复未经验证；硬崩溃不能保证恢复。

## 系统策略

“我的电脑”显示可用的硬件信息与 Windows 策略。选择电源计划，或为进程选择支持的优先级；仅在支持时提供亲和性设置。进程身份同时使用 PID 和创建时间。RealTime 优先级及不支持的多处理器组亲和性写入会被拒绝。

**恢复原始策略** 只恢复当前仍与光序写入值一致的属性，保留其他软件随后做出的更改。重启后复用同一个 PID 的进程不会被视为原进程。

## 关闭、恢复、更新与卸载

- 关闭窗口会隐藏到托盘。
- **退出界面** 只关闭桌面应用，服务继续运行，也不会延长风扇会话。
- 设置中的 **恢复并退出** 会尝试恢复支持释放的控制器和已知同步前灯光。失败时保留窗口与错误信息。它不会停止 Windows 服务，也不能恢复未知的原始灯光。
- 更新或修复时，先退出界面，再使用 `--install` 参数运行下载的安装程序。无参数打开会启动已有安装。安装程序先停止服务再替换文件；具体升级范围以版本说明为准。
- 在 Windows“已安装的应用”中卸载，或运行已安装的 `LightOrder.exe --uninstall`。卸载需要提权，会停止并删除服务。当前实现保留偏好和程序文件；手动清理前需退出所有 LightOrder 进程。独立安装的依赖需单独处理。

## OpenRGB 与 PawnIO

内存灯光使用 `127.0.0.1:16742` 上的 OpenRGB SDK v3，仅接受 ENE SMBus DRAM。受管理后端需要兼容的 OpenRGB 程序、与该构建完全一致的完整检测器清单，以及正在运行的 PawnIO 驱动。

发行说明必须写明是否含 OpenRGB 和 PawnIO 安装程序。源码构建不会自动下载它们。打包时提供已签名的 PawnIO 安装程序后，安装流程可以调用它并启动已安装驱动；这本身不能证明版本、发布者身份或硬件兼容性，发布者仍须核验来源。不需要关闭 Windows 安全功能。

管理员可以在已安装的 OpenRGB 插件旁配置 `backend.json`。可执行文件、配置和数据目录必须受保护，不能把特权后端指向普通用户可写的程序。下面是独立安装可信 OpenRGB 的示例：

```json
{
  "executablePath": "C:/Program Files/OpenRGB/OpenRGB.exe",
  "sourceConfigPath": "C:/Program Files/LightOrder/plugins/OpenRgb/detectors.json",
  "dataDirectory": "C:/ProgramData/LightOrder/OpenRgb",
  "requestTimeoutMs": 5000
}
```

不提供该文件时，默认使用插件旁的 `runtime/OpenRGB.exe` 与 `detectors.json`，状态位于 `%ProgramData%\LightOrder\OpenRgb`。服务只部署可信插件；旧版适配器 CLI 或环境变量配置不能作为绕过受保护部署的方式。可选输入路径见[发布指南](build-and-release.md)。

检测器清单必须包含对应 OpenRGB 版本的全部检测器。适配器只启用 `ENE SMBus DRAM`，启用 HID 安全模式，并禁用 ENE 持久保存。上游可能默认启用旧清单未列出的新检测器，因此不能混用旧清单。请自行关闭竞争的 RGB 控制程序；光序不会结束其他用户的 OpenRGB 实例。

## 故障排查

| 现象 | 检查内容 |
| --- | --- |
| 服务未连接 | 在 Windows 服务中检查 `LightOrder.Service`，再使用“设置 → 安装与修复”。用安装所属账户重新连接。 |
| WebView2 错误 | 安装或更新 Evergreen Runtime，再打开安装程序。 |
| 插件断连 | 记录错误分类。检查设备和此前结果不确定的写入，再重启服务；重连先读取状态。 |
| 没有内存灯光 | 检查发行依赖、PawnIO 状态、受保护的 OpenRGB 路径、检测器清单和其他 OpenRGB 进程。 |
| 没有风扇编辑器 | 主板、通道映射、权限或基线没有通过检查。只读状态是预期行为。 |
| 无法确认恢复 | 保留错误详情，不能从进程退出或重启推断恢复成功。检查实际风扇行为及硬件正常控制路径。 |

报告应包含应用与插件版本、Windows 版本、硬件型号、操作步骤、错误分类，并说明依据来自软件还是实物。公开日志和截图前，请去除账户 SID、个人路径、进程名称及其他隐私信息。
