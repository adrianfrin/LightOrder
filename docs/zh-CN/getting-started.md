# 开始使用

[English](../en/getting-started.md) · [首页](../../README.zh-CN.md)

## 安装与启动

1. 使用 Windows 11 x64，安装 [Microsoft Edge WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。安装程序会检查，但不会静默下载。
2. 从 [Releases](https://github.com/adrianfrin/LightOrder/releases) 下载 `LightOrder-win-x64.exe`，阅读依赖、验证记录和 SHA-256。
3. 用日常 Windows 账户运行并批准管理员授权。受保护的工作进程安装 `LightOrder.Service`、插件及应用，随后尝试使用该账户已有的未提权 Explorer 令牌启动界面。无法取得此令牌时，安装程序报告完成，并提示手动重新打开光序。
   安装程序创建桌面与开始菜单快捷方式，直接启动普通权限界面，并注册 Windows“已安装的应用”入口。
4. 在设置检查服务连接。发现过程读取设备。**启动时恢复灯光** 与 **启动时恢复散热** 分别主动开启，默认均为 false。开启后只向合格的已发现设备请求保存的设置，失败不重试。存在未完成的灯光操作时，会跳过启动灯光恢复。
5. 先检查设备实际支持的控件。OpenRGB 发现时可能启动配置的后端，但发现本身不设置灯效。

自包含包包含 .NET；WebView2 仍是前置条件。构建成功不能证明干净机器的安装、更新或卸载。

## 灯光

选择设备及静态、呼吸、彩虹或关闭，调整颜色/亮度，再 **保存并应用**。草稿编辑不写硬件。亮度按比例缩放 RGB，不是测得的光强。呼吸和彩虹由服务生成静态帧，目标每秒 4 帧，最多 16 台设备，周期 2–60 秒，默认 6 秒。设备延迟可能降低帧率。某台设备的帧失败后停止该动画，不自动重试。

同步需要主动开启，至少选择两个已有独立设置的合格设备。原状态未知时先保存独立设置。选择成员、编辑组并保存。关闭同步后保存并应用，恢复已知的同步前设置。这些是光序已知的设置，不是不可读取的出厂颜色。同步动画可共用相位，但不保证硬件级同步时序。

保存菜单可创建场景，用于复用或自动化。部分失败会明确保留，请检查设备再重试。命令接受或 OpenRGB 缓存匹配不能证明实物变化；不自动重放不确定的写入。

## 散热

只有声明 `fan.profile` 的设备可编辑。选择冷排/机箱、曲线或手动百分比，再保存并应用。曲线含 2–12 个点，温度递增、占空比不下降，终点为 80°C / 100%。冷排最低 40%，机箱最低 25%。静音在 80°C 保护阈值以下固定为冷排 40%／机箱 25%；平衡通过温度滤波、迟滞与限速调节。全部模式在原始温度达到 80°C 时立即满速保护。水泵转速只读，占空比不等于固定 RPM。

现在采用 **持续控制**，没有固定时长或更新次数上限，退出界面后仍继续。**恢复原始控制**、服务关闭及安全故障会尝试恢复，请检查返回结果。

温度/转速缺失、过期、歧义、无效或风扇故障会触发恢复。挂起通知或超过五秒的控制间隔会先恢复，再用新鲜实测温度重启。未解决的持久化恢复意图阻止新接管。硬崩溃不能保证恢复；新代码的长时间运行与睡眠唤醒硬件验证仍待完成。详见[散热与恢复](cooling.md)。

## 自动化

在 **自动化** 中创建定时或精确进程规则，再主动启用；新规则默认不启用。动作可组合保存的灯光场景、受支持散热预设、电源计划与进程策略。定时只在准确的本地分钟运行；进程规则只处理新观察到的安装所属账户进程身份。退出动作使用保存时快照。至多一次派发、漏过触发、多实例、暂停与恢复详见[自动化指南](automation.md)。

## 系统策略与偏好

“我的电脑”显示硬件信息与 Windows 策略。选择电源计划，或为进程设置支持的优先级；仅在支持时提供亲和性。PID 加创建时间标识进程。RealTime 优先级及不支持的多处理器组亲和性写入会被拒绝。

**恢复原始策略** 只恢复仍与光序写入值一致的属性，保留外部程序后续修改。复用 PID 不会继承旧进程身份。设置提供语言、外观、启动恢复选项、服务诊断和安装/修复入口。

## 关闭、恢复、更新与卸载

- 关闭窗口隐藏到托盘。**退出界面** 后，持续散热、灯光动画、自动化和服务仍运行。
- **恢复并退出** 尝试释放控制器及恢复已知同步前灯光，失败时保留窗口。它不停止服务或禁用自动化，已启用规则随后仍可能应用设置。如需阻止后续变化，请先禁用规则。
- 更新/修复时，双击下载的安装程序，或用 `--install` 运行。安装目录内的启动器无参数打开已有安装。受保护的暂存工作进程等待启动器退出，停止服务、关闭准确匹配的已安装进程，再替换文件。保留原 owner SID、启用插件与偏好。安装程序尝试以普通权限重新打开界面；出现提示时请手动打开。
- 在 Windows“已安装的应用”卸载，或运行已安装的 `LightOrder.exe --uninstall`。提权工作进程停止并删除服务、关闭已安装进程、删除程序文件和卸载项，并移除准确匹配的光序快捷方式/启动命令。对话框可选择保留或删除 ProgramData 偏好、配置、自动化/后端数据及所属账户的本地光序数据。删除所属账户本地数据需要能解析其 Windows 配置文件；清理该账户的 Run 启动项需要其注册表配置单元已加载。共享 PawnIO 和 WebView2 保留。暂存助手安排在重启时清理。未解决的风扇恢复意图或未完成的服务删除会阻止文件清理，并保留恢复证据。

以上说明反映源码行为，仍需对具体包体进行干净机器验证。停止或进程退出本身不能证明硬件已恢复。

## OpenRGB 与 PawnIO

专用 OpenRGB SDK v3 监听 `127.0.0.1:16742`，默认开放 ENE SMBus DRAM。其他实物设备需要管理员显式配置。受管理后端需要兼容程序及与该构建完全一致的完整检测器清单。启用的检测器含 SMBus 时，需要正在运行的 PawnIO 驱动。

发布说明应写明 OpenRGB 和 PawnIO 是否随包提供。源码构建不自动下载它们。打包提供已签名 PawnIO 安装器时，安装可调用并启动驱动；发布者仍需验证来源和兼容性。无需关闭 Windows 安全功能。

管理员可在已安装 OpenRGB 插件旁放置 `backend.json`：

```json
{
  "executablePath": "C:/Program Files/OpenRGB/OpenRGB.exe",
  "sourceConfigPath": "C:/Program Files/LightOrder/plugins/OpenRgb/detectors.json",
  "dataDirectory": "C:/ProgramData/LightOrder/OpenRgb",
  "requestTimeoutMs": 5000,
  "enableEneDram": true,
  "additionalDevices": []
}
```

路径须为受保护的本地绝对路径，不能指向普通用户可写的可执行文件。不提供该文件时，默认使用插件旁 `runtime/OpenRGB.exe` 和 `detectors.json`，数据位于 `%ProgramData%\LightOrder\OpenRgb`。CLI/环境覆盖不能绕过受保护部署。

适配器禁用允许列表以外的检测器，启用 HID 安全模式，禁用 ENE 持久保存。每个配置的检测器都必须存在于匹配版本的完整清单中，旧清单不足。精确扩展规则见 [OpenRGB 设备策略](plugin-development.md#openrgb-设备策略)。配置不代表全部硬件兼容。请自行关闭竞争控制程序；光序拒绝与其他 OpenRGB 实例竞争，不会终止它。

## 故障排查

| 现象 | 检查内容 |
| --- | --- |
| 服务未连接 | Windows 服务中的 `LightOrder.Service`，再使用设置中的安装/修复，以安装所属账户重连。 |
| WebView2 错误 | 安装/更新 Evergreen Runtime，再打开安装程序。 |
| 插件断连或动画停止 | 记录诊断；重启前检查设备及此前不确定的写入。 |
| 没有 OpenRGB 设备 | `BackendDiscovering` 表示等待发现，服务每 15 秒重试、不设置灯效；其他情况检查精确允许列表、清单、受保护路径、所需 PawnIO 状态及竞争进程。 |
| 无风扇编辑器 | 主板、通道、权限、基线或未解决恢复意图可能阻止控制，只读是预期行为。 |
| 规则暂停 | 处理诊断原因后显式保存，不要删除执行日志来重置。详见[自动化](automation.md)。 |
| 无法确认恢复 | 保留错误，检查实际风扇和固件正常控制；进程退出/重启不能作为证明。 |

报告应包含版本、Windows 版本、硬件、操作、错误分类，并区分软件与实物证据。公开日志/截图前去除 SID、个人路径、进程名称及其他隐私。
