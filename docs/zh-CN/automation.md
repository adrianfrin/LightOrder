# 自动化

[English](../en/automation.md) · [开始使用](getting-started.md) · [插件契约](plugin-development.md) · [首页](../../README.zh-CN.md)

Windows 服务执行已保存的规则，桌面界面关闭后仍可运行。规则包含设备命令，不包含脚本或启动程序命令。先用单个设备确认结果，再组合多个动作。

## 创建规则

1. 如果需要改变灯光，先在灯光页的保存菜单中创建场景。
2. 打开 **自动化 → 新建规则**，填写名称，选择定时或进程触发。
3. 定时规则选择本地 `HH:mm` 时间和重复日期。进程规则填写完整文件名，例如 `game.exe`，不能填写路径或通配符。
4. 选择灯光场景，也可组合受支持的散热预设、电源计划或进程优先级/亲和性。只有进程触发可以设置进程策略。
5. 进程规则可将当前已知的灯光、散热和电源设置记录为退出动作。快照在保存规则时取得，不会持续记录随后发生的全部变化。
6. 启用并保存规则，在触发后检查执行状态。新规则的编辑器默认不勾选启用。

场景内容会复制进规则，之后修改场景不会自动修改规则。禁用或删除规则只阻止后续触发，不会撤销已经应用的设置。关闭窗口或退出界面后，服务仍继续执行规则。

## 定时语义

服务约每秒检查一次。规则只在 Windows 本机时区中选定日期的准确分钟内运行。睡眠、停机或控制循环延迟错过的分钟不会补执行。

服务在首个设备命令前，先持久化占用该日期的执行机会。同一规则 ID 每个本地日期至多执行一次，包括夏令时重复小时和时钟回拨。编辑规则和服务重启会保留同一 ID 的日期高水位。时钟向前跳跃后，规则可能需要等到本地日期超过已记录日期才再次运行。

这是至多一次派发，不保证成功执行。预留后崩溃可能导致没有动作执行，或只执行部分命令。重启时遗留的 `running` 状态变为 `paused`，服务不会重放结果不确定的写入。

## 进程身份与退出动作

按完整 `.exe` 文件名匹配，忽略大小写，只读取属于安装所属 Windows SID 的交互式进程，不监控所有用户。身份为 **PID 加 UTC 创建时间**，复用 PID 不会沿用旧身份。快照来源不返回或记录命令行、用户名及完整可执行路径。

服务启动或任何显式规则保存后的首次成功进程快照，会为已启用的进程规则建立基线。该快照中的实例不补执行启动或退出动作，包括保存后、首次轮询前打开的实例；之后新观察到的实例才可触发动作。保存任意规则都会重置全部规则的进程跟踪，此前激活的实例不再通过该跟踪执行退出动作。两次轮询之间完成启动与退出的短命进程可能被漏过。

每个新观察到的实例执行启动动作。`process.policy` 的 `pid` 和 `startTimeUtc` 由服务填写，规则不能提供。只有已激活实例消失且没有匹配实例存活时，才运行退出动作。某实例退出时若还有其他实例，其退出动作会被抑制。退出动作不能写 `process.policy`，也不能调用全局 `device.release`。Windows 策略适配器单独清理已退出进程的身份。

## 失败与上限

命令按顺序执行。跨设备没有事务，也不会自动回滚前面的成功动作。命令失败、结果不确定或进程快照不安全时，相关规则暂停并记录原因。执行日志写入失败会暂停全部自动化。日志不可读时需要可信恢复，不会被静默覆盖；已保存规则缺少日志时，需要显式保存才能解除阻止。

处理原因后，显式保存规则可重置暂停状态。保存不会补执行旧进程事件或错过的定时分钟；若当天尚未预留执行机会，后续匹配分钟仍可触发。进程快照失败不阻止独立的定时规则。

上限：格式版本 1，规则文档 128 KiB，64 条规则，每条 1–16 个启动动作、最多 16 个退出动作，执行日志 4 MiB，每次快照 4,096 个进程，每条规则 256 个匹配身份，每轮最多 16 个新匹配实例。超出突发上限会暂停规则，不建立待补执行队列。日志保留已删除规则的 ID 及日期高水位，累计最多 1,024 个规则 ID。反复新建 ID 可能耗尽此预算，删除规则不会回收预算。

## 服务接口与存储

- `app.automation.read {}` 返回 `{schemaVersion,rules,status}`，状态包括 `disabled`、`ready`、`running`、`completed`、`paused`。
- `app.automation.write` 接收 `{schemaVersion:1,rules:[...]}`。设备 ID 必须来自当前发现结果，格式为 `pluginId::localId`，能力必须能路由到对应设备。
- 规则字段为 `{id,name,enabled,trigger,commands,exitCommands?}`。定时条件为 `{kind:"daily",time:"20:00",days:[0,1,2,3,4,5,6]}`，0 代表周日；进程条件为 `{kind:"process",processName:"game.exe"}`。
- 动作使用[标准契约](plugin-development.md)的 `{deviceId,capability,parameters}`，不能把示例 ID 或枚举序号当成真实设备身份。

受保护文件位于 `%ProgramData%\LightOrder\automation.json` 与 `automation-journal.json`。写入先刷入临时文件，再替换目标文件。执行日志保存防重证据，不应通过删除它来进行普通重置。
